1. プロジェクト概要

システム名称 家計簿（家計簿＋TODOリスト＋日記）
目的・コンセプト 日々の家計・TODO、および日記を管理できるWebアプリケーション。
月の予算管理や日割りの使用可能額を可視化し、予算達成時には達成感を感じられる仕掛けを提供する。
想定技術スタック
  • フロントエンド: HTML5, CSS3, JavaScript (ES6+), Chart.js (グラフ描画)
  • バックエンド: Python (FastAPI) または Node.js (Express)
  • データベース: PostgreSQL
  • 認証方式: セッション認証 または JWT認証

2. 画面構成・ルーティング (サイトマップ)

画面・ページ名 パス (URL) 機能・詳細内容
ログインページ /login
  • ユーザーID（メールアドレス）およびパスワード入力による認証
  • ログイン成功時、カレンダー(Monthly)ページへ遷移
家計簿入力・予算設定ページ /budget
  • 月次予算設定: 該当月の「収入」「固定支出」「変動支出」「投資・貯蓄」の目標額を入力・保存
カレンダー(Monthly)ページ /calendar/monthly
  • 月単位収支一覧: 日ごとの合計支出を表示。日付クリックで Day ページへ遷移。
  • 月の詳細・現時点の収支: 当月の累計収入・支出・投資貯蓄の表示
  • 残使用可能額: 当月の残り使用可能額（月合計）および日割り残額のリアルタイム表示
  • モチベーションステータス: 日割り予算の使用率に応じた3段階ステータス表示
  • 月間メモ欄: 自由記述テキスト
カレンダー(Day)ページ /calendar/day/:date
  • 指定日（YYYY-MM-DD）の家計簿データ入力（費目別金額・メモ）
  • 指定日の日記記述・閲覧
TODOページ /todo
  • タスク管理: 今月やること、買い物リストなどの一覧表示・追加・編集・削除
  • 完了処理: 完了タスクはチェックボックスで判定し、テキストをグレーアウト＆打消し線表示
年月日支出分析ページ /analytics
  • 指定した年月日の支出データ集計
  • Chart.jsを用いた固定支出・変動支出の内訳（円グラフ／棒グラフ）の視覚化

3. 機能要件・ビジネスロジック仕様

3.1. 費目設定（マスタ固定）

※ユーザーによる費目の新規追加・変更は不可とし、システム固定とする。

分類 設定費目一覧
固定支出 家賃、ガス代、電気代、水道代、通信費、保険、教育費、その他
変動支出 食費、衣服、趣味、交通費、医療費、交際費、美容費、日用品、その他
収入 / 投資・貯蓄 収入、投資貯蓄

3.2. 入力UI・視覚化要件

項目 詳細仕様
入力インターフェース ボタン形式で「固定支出」「変動支出」「収入/投資」の分類を最初に選択し、対応する入力フォームに遷移・展開させる。
データの視覚化 年月日支出ページにて、カテゴリ別・費目別の支出割合をグラフ（円グラフ等）で動的に描画する。
計算ロジック
  • 当月利用可能残額 = 月の変動費予算 - 当月の変動費累計支出
  • 本日利用可能額（日割り） = 当月利用可能残額 / 当月残日数（本日含む）
  • 本日使用率(%) = (本日の変動費支出額 / 本日利用可能額) × 100
モチベーション要素
（ステータス判定基準）		 本日使用率(%)の範囲によって、表示するステータスアイコンを切り替える。
  • 良い (siseiyoi.png): 本日使用率 0% 〜 70% 未満
  • 普通 (nesoberi.png): 本日使用率 70% 〜 100% 以下
  • 悪い (nekoze.png): 本日使用率 100% 超（予算オーバー）

5. AIプロンプト実装制約 (開発指示事項)

項目 指示内容
セキュリティ パスワードは必ず bcrypt 等でハッシュ化してデータベースに保存すること。
エラーハンドリング 画像ファイル（例: img/siseiyoi.png 等）が存在しない場合でも描画エラーを起こさず、フォールバックの絵文字（例: 良好: 姿勢良い, 普通: 寝そべり, 悪い: 猫背）を表示できる設計とすること。
コード生成順序 1. DBテーブル定義（DDL） → 2. バックエンドAPI実装 → 3. フロントエンド画面・UI実装 の順で生成を行うこと。
